# Claude Code features relevant to a self-continuing loop (fetched 2026-10-25 by a guide agent)

Headline facts, each with its doc page:

- Auto-compaction does not end the session; 1M-window models compact at about 967K tokens by default; `autoCompactWindow` (100K to 1M) and `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` lower it. (context-window.md, model-config.md, env-vars.md)
- A SessionStart hook with the `compact` matcher runs after compaction and its stdout is added to the compacted context; the hooks guide shows `echo`, so `cat handoff.md` fits. Output over 10,000 characters may be replaced with a file path (unconfirmed for SessionStart). PreCompact and PostCompact cannot inject context. (hooks.md, hooks-guide.md)
- What survives compaction: project-root CLAUDE.md, auto memory, up to five recently edited files, invoked skill bodies (5K per skill, 25K total). Hook-added context is summarized, not re-injected. (context-window.md)
- No documented standing compaction instructions in CLAUDE.md or settings; `/compact <focus>` is the only instruction channel.
- Headless: `claude -p` with `--resume <id>`, `--continue`, `--session-id`, `--fork-session`, `--max-turns`, `--output-format json` (carries `session_id`, `total_cost_usd`); a prompt file on stdin up to 10MB. Documented chaining: capture `session_id` from one run, resume in the next. (headless.md, cli-reference.md)
- No hook starts a successor session. Stop hook can block the stop up to 8 times (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`); SessionEnd cannot block. `/goal <condition>` keeps one session working until a small model judges the condition met, and `claude -p "/goal ..."` runs it to completion. (hooks.md, goal.md)
- `--bare` skips CLAUDE.md, hooks, skills, subagents, auto memory; from v2.1.302 `-p` starts in Manual mode and denies prompts unless `--permission-mode auto`, `--allowedTools`, or `--permission-prompts none`. `-p` runs never clean up worktrees. (headless.md, worktrees.md)
- Subagents: fork mode on by default from v2.1.302 (inherits the full conversation; a fork cannot spawn forks); `isolation: "worktree"` branches from the default branch unless `worktree.baseRef` is `head`; custom agents in `.claude/agents/*.md` with `model`, `effort`, `tools`, `maxTurns`, `autoCompactWindow`, `isolation`, `memory`, `background`; nesting up to three layers (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`); 20 concurrent per session (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`); results return to the caller only, transcripts at `~/.claude/projects/{project}/{sessionId}/subagents/`. `SendMessage` resumes a subagent. (sub-agents.md, tools-reference.md)
- Agent teams: experimental, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, interactive sessions only, one team per session, a fixed lead, teammates as separate instances with a shared task list and mailboxes under `~/.claude/teams/`; split panes unsupported in VS Code's terminal and Windows Terminal. (agent-teams.md)
- Cross-session messaging: on by default (native Windows v2.1.234+); two interactive sessions on one machine can message each other via `ListAgents`/`SendMessage`; a `-p` worker with `crossSessionInbound: accept` can receive unattended; peer messaging only, no lead/worker hierarchy; WSL 2 and native Windows sessions cannot reach each other. (cross-session-messaging.md)
- Worktrees: `claude --worktree <name>` creates `.claude/worktrees/<name>/` on branch `worktree-<name>`; `claude --worktree "#1234"` from a PR; while in a worktree, edits and shell commands against the main checkout are blocked, subagents included; sessions share `.git`; interactive exit cleans a clean unnamed worktree. (worktrees.md)
- Scheduled cloud tasks (`/schedule`, `RemoteTrigger`): research preview, 100 scheduled runs per hour per account, API trigger via HTTP POST; cloud runs start in auto mode. `claude --cloud "<task>"` creates a cloud session (bundles the repo when no remote); `claude -p ... --cloud <session-id>` queues a message; a terminal session cannot be pushed to the cloud. (routines.md, claude-code-on-the-web.md)
- Workflow tool: JavaScript script with `agent()`, `pipeline()`, `parallel()`, `phase()`; 16 concurrent agents default, 1,000 per run; no mid-run user input ("for sign-off between stages, run each stage as its own workflow"); resume reuses completed agents' results. Needs an allow rule in `-p`. (workflows.md)
- Agent SDK: Python `claude-agent-sdk`, TypeScript `@anthropic-ai/claude-agent-sdk`; runs the Claude Code binary in a process you host; `continue`, `resume`, `fork_session` options; `error_max_turns`, `error_max_budget_usd`; API key auth required for products. (agent-sdk/overview.md, agent-sdk/sessions.md)
- Effort: `/effort`, `--effort`, `CLAUDE_CODE_EFFORT_LEVEL`, `effortLevel` and `maxEffortLevel` in settings, per-model `modelSettings`; Opus 5.5, Sonnet 5.5 and Haiku 5.5 default to `medium`, other models to `high`; subagent frontmatter `effort` and the Agent tool's per-call `effort`; model aliases `sonnet`, `opus`, `haiku`, `fable`, `inherit`; `CLAUDE_CODE_SUBAGENT_MODEL`. (model-config.md, sub-agents.md)

Not found in the docs: a hook that launches `claude -p`; a subagent option writing results to a file; a serial implement-review-merge workflow example; a lead/worker model in cross-session messaging.
