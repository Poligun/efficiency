## 6. Generic lessons

- A reviewer that reads primary material the author skipped finds the real defects; a reviewer that only reads the diff finds nits. The six findings that changed behaviour in this session each came from a reviewer that ran the script, grepped the fixtures by section, or read the upstream loader source. Review prompts should say what primary material exists (local checkouts, fixtures, generated outputs) so that reviewers do not download what is already on disk.
- Skipping the dispatched logic agent on a "small" diff costs a round. PR #24's round 1 skipped A3 and missed the one HIGH; round 2 dispatched it and found it in three minutes. The skill's "still dispatch business logic" rule exists for exactly this case.
- Documentation written in under a minute needs the same review as code. PR #27 (docs and LICENSE only) carried three factual errors and PR #26's ADR edit left two contradictory version numbers after the author's own grep. The loop's "light PR gets `/code-review` at medium" tier was enough to catch them, which argues for keeping that tier rather than exempting docs.
- Root-cause findings beat workaround findings and arrive late. The bazelisk 1.17 problem was documented as a three-place workaround in PR #23, flagged as duplication by that review, and solved only when PR #26's reviewer asked why the workaround existed. A reviewer prompt that asks "is there a mechanism that removes this workaround" would have saved a PR.
- Hardcoded interpreter names in review tooling cost every round. `python3` is absent on this Windows host, so four reviewers each lost one or two tool calls, and one lost the scope script entirely. Skill scripts should probe `py -3`, `python`, `python3` once.
- Known shell pitfalls recur unless the harness blocks them. The user's memory warns about backslashes in Bash heredocs; the agent still lost three heredocs (apostrophe, escaped string, backslash) and recovered each time with Write or Edit. Starting from Write for any multi-line file content would have avoided all three.
- Status reports to an absent user are the main avoidable output cost. Seven reports of 300 to 500 words restated PR bodies and PR comments that already existed; the stats show 518 K output tokens for 1,951 added lines. One report per pause, plus the PR links, would carry the same information.
- A continuation prompt must be reprinted whole at the real end of the session. Ending with "the earlier prompt still applies, except..." leaves the next session with a stale "Waiting on" line and two conflicting states to reconcile.
