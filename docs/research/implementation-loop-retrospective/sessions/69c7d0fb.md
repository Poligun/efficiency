## 6. Generic lessons

- A blocking question should come after the work that does not depend on it, or be phrased as a default the user can veto. The 175-minute stall at 19:35:54 was the single largest cost in the session and six of seven findings in that round could have been fixed first.
- The code the user tests must be the code that merges. PR 37 was tested in game on a binary from before the second review's fixes, and PR 44 was merged after a rework nobody reviewed. The loop needs an explicit "rebuilt after the last change" check before the human gate.
- Each review round found real bugs, including bugs the previous round's fixes introduced (PR 40 R2 F2 followed R1 F3; R3 F2 followed R2 F3). Rounds are worth their 100,000 output tokens, but the verifier and knowledge-base steps of the skill never ran in six runs, so the skill text describes a process that does not happen on this harness. Either make verifiers and the knowledge base run, or remove them from the skill so Coverage lines stop reporting their absence.
- Whole-file rewrites and heredoc edits are the token and error drivers. Five backslash-collapse incidents happened after a memory note said to write scripts to a file first; a rule that is only in memory is not a rule. A hook or a check in the loop doc that forbids heredoc edits of files containing backslashes would have saved around fifteen tool calls.
- Reviewing GUI code is not the same as running the window. Three opus reviewers missed five defects that the user saw in one look. A loop that builds a GUI should run it, or render a screenshot, before asking the user to.
- Instructions for a human tester need the setup explained on first use (where the binary is, what to paste where, what each variable holds, what a redirected command prints). The memory saved at 02:26 captures this, but the two clarification turns it would have prevented happened at 18:27 and 18:29.
- User-facing text should define a term once in the user's own words or avoid it. "package", "slug", "gate", "profile", "slot" and "clash" were never defined where the user would read them, and the user's questions ("why is it on the same level as library tab", "The integer numbers are hard for human to understand") show the vocabulary gap turning into design questions late.
- The context-free reviewer worked as designed: a finder that was not anchored on the author's thesis looked at the live install and found the RabbitFX namespace bug. The design is only context-free at the top, since nested finders receive the top-level thesis; that is acceptable, but the top-level reviewer's thesis should be kept short so it does not become the anchor it was meant to avoid.
