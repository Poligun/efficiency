## 6. Generic lessons

- A fix round that is reviewed as `HEAD~1..HEAD` reviews the fix's side effects in isolation and tends to produce findings the previous round's fixes created. On #46, eight of thirteen round-2 and round-3 findings were fallout from the round before. Either review the whole branch each round, or cap rounds and merge once the remaining findings are mechanical.
- A review skill's effort argument has to be checked, not trusted. Every `/code-review` here was asked for "medium" and ran with a "high effort, recall, no verify" banner, and the unverified round (#46 R2) returned nine findings with a false positive that only the next round's verification removed. Adding "check each finding against the source" to the dispatching prompt halved the surviving lists; make that line standard.
- `/deep-code-review` as installed never ran its own fan-out: both deep reviewers chose inline reading on 800 to 1100-line diffs, skipping the convention ledger, the verifier batches and the business-logic subagent the skill mandates. The findings were still good, so the question for the skill is whether the dispatch rules should bind at medium effort or be cut to match what agents do.
- Linter limits belong in the build reference. A 100-line clippy cap cost four refactor cycles in one session because `agents/build.md` names the clippy targets but not the thresholds; the same applies to the rustfmt binary's location under the test runfiles, which the agent re-derived from scratch.
- A memory note about shell quoting is not enough; the session hit the backslash-collapse class three times before switching to Write-then-`python -I`. The continuation prompt now states the rule directly; CLAUDE.md or the loop file should, too.
- Design questions batched once per task work, but eight of eight answers took the recommended option and the second batch cost 17 minutes of wall-clock. When every option carries a recommendation the agent is sure of, it should state the plan and pause only on the fork it cannot settle.
- The loop's 3.2 (an unwritten convention is a pause condition) was not applied to the CLI flag-parsing rule, which changed three times across rounds. A reviewer disagreement that flips a rule twice is the signal to write the convention down or ask.
- Merge-then-check for changes that need an in-game check leaves `main` carrying unverified behaviour. The loop should say whether the check gates the merge or follows it.
