1. The loop's re-review rule has no termination condition. The loop says "Do not widen scope into a neighbouring ticket; file a new one instead", and question 4's third option ("Primary only, drop merge") would have done that, but the agent recommended against it.

## 6. Generic lessons

- A re-review rule needs a budget and a stop rule, not only a trigger. "Re-review when fixes changed logic" is satisfied forever on a logic-heavy PR; PR 30 ran six rounds and the agent improvised its own stop at round 5. Cap rounds, or re-review only the delta.
- Fix rounds that add features restart the review. The PR grew by 1,150 inserted lines across its fix rounds, and every HIGH after round 1 was in code a fix round had added. Review findings that ask for a new mechanism (a lock, a merge, redirects) should become tickets, as the loop already says for scope.
- A reviewer's NEEDS-DECISION question is the author's decision only when the ticket covers it; otherwise it is the user's. Two agent-made decisions here (join neither; stable ids via redirects) each cost two further rounds.
- Context-free reviewers are accurate but amnesiac. The nine rounds re-read the crate nine times, reversed two policies, and re-raised a declined finding. Pass the previous round's report and the author's disposition comment to the next reviewer, and let the loop prompt stay free of the author's summary.
- Questions to the user must define their terms at the moment they are asked. The user chose, reversed and re-chose the label key because "key", "variable" and "scope" were undefined; the explanation that worked came 28 minutes later. Three of three multiple-choice answers were the recommended option, which is what a reader does when the question is opaque.
- The skill's expensive parts were skipped in every run (verifiers, convention scout, haiku tiers) and the skill's scope script failed on Windows in every run. Either the skill should state that single-reviewer mode is acceptable for a focused repo, or the loop should check that the skill ran as written; today the Coverage paragraph is the only evidence and it has to be read each time.
- Do not stop the loop without a pause condition. The agent printed a continuation prompt after one PR with a warm cache and half its context unused, and the user had to restart it.
- Environment facts that fail identically every time (python alias, cp1252, 7-Zip off PATH, heredoc backslashes) belong in `agents/build.md` or the skill, not in memory notes the agent still ignores twice.
